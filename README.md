# CourtHub

CourtHub is a full-stack sports court booking platform. Customers can discover venues, view court availability, and create bookings. Partners can manage their venues and courts, while administrators manage the platform.

The project is intentionally implemented as a modular monolith so it remains practical to learn, deploy, and maintain while still covering real-world full-stack concerns.

## Architecture

The repository is organized as a super repository with two Git submodules:

- `frontend/` — Next.js, TypeScript, App Router, Tailwind CSS, shadcn/ui, TanStack Query, React Hook Form, and Zod.
- `backend/` — NestJS REST API, JWT authentication, role-based authorization, Drizzle ORM, and PostgreSQL.
- PostgreSQL — local development database or Supabase PostgreSQL.

The backend is divided into business modules and uses a repository layer as the only database access layer:

- Authentication and users
- Venues and courts
- Bookings
- Administration

## Roles

- `GUEST` — can book without an account by providing contact information.
- `CUSTOMER` — can register and sign in with an email address or phone number, then view booking history.
- `PARTNER` — can manage venues, courts, prices, operating hours, and booking requests.
- `ADMIN` — can manage users, partners, venues, and bookings.

## Main features

- Venue search by name, location, and sport type
- Court details, hourly prices, and availability
- Guest and authenticated-customer bookings
- Booking cancellation and status management
- Partner venue and court management
- Admin dashboard and venue approval
- JWT authentication and role-based authorization
- UUID v7 generated by the application
- Swagger API documentation
- Jest unit tests and Husky pre-commit checks

## Local development

### Prerequisites

- Node.js 20 or newer
- npm
- PostgreSQL 15 or newer, or a Supabase PostgreSQL database

### Backend

```bash
cd backend
copy .env.example .env
npm install
npm run db:migrate
npm run db:seed
npm run start:dev
```

The API runs at `http://localhost:8386/api`.

Swagger documentation is available at `http://localhost:8386/api/docs`.

### Frontend

```bash
cd frontend
copy .env.example .env.local
npm install
npm run dev
```

The web application runs at `http://localhost:3000`.

On macOS or Linux, replace `copy` with `cp`.

## Booking integrity

Bookings use `start_at` and `end_at` timestamps in 30-minute intervals. The backend checks for overlapping active bookings before creating a booking and returns `409 Conflict` when the requested period is unavailable.

UUID v7 values are generated by the application and supplied explicitly in every insert. The database does not generate IDs.

## Quality checks

Each submodule has its own ESLint, Prettier, and Husky configuration. The pre-commit hook runs lint-staged on staged files.

Useful backend commands:

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

Useful frontend commands:

```bash
npm run lint
npm run build
```

## Scope exclusions

The initial version does not include online payments, chat, promotions, reviews, AI recommendations, realtime infrastructure, microservices, Kafka, or Kubernetes. These can be added in later phases after the core booking flow is stable.
